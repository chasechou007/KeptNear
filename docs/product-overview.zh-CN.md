# KeptNear 产品说明

[English](product-overview.md) | [简体中文](product-overview.zh-CN.md)

- 文档状态：产品方向已确认
- 当前发布成熟度：实验性 pre-alpha
- 当前二进制预览版：`v0.1.0-prealpha.2`

## 一句话说明

KeptNear 是一个本地密码与令牌管理器：凭据保存在用户控制的加密密码库中，
并由用户决定哪些本地应用和工具可以使用哪些密钥字段。

## 为什么开发 KeptNear

KeptNear 源于一个简单的信念：如果密码库属于用户，用户就应当能够把它保存在
自己控制的位置，并自行选择如何在自己的设备之间传输加密文件。

本地优先的密码管理器保留了这种控制权，但很多产品没有同时提供现代、原生的
日常体验。与此同时，开发者令牌散落在 shell 配置、`.env` 文件、不同工具设置、
项目文档和 Agent 对话中。把 Token 粘贴进 AI 对话，或者通过工具结果直接返回，
都会增加新的泄露面。

因此，KeptNear 把两个相关任务放进同一个产品：

1. 为人提供现代的本地密码管理器。
2. 为本地应用和工具提供受控的凭据使用代理。

KeptNear 不把自己定义为“AI 密码管理器”。Codex、Claude Code、其他 Agent、
MCP Host、CLI 工具和普通桌面应用，都是凭据使用方（Consumer）。KeptNear
控制它们能否使用凭据，但不判断它们的意图，也不会修改它们的指令文件。

## 产品承诺

KeptNear 围绕五项承诺设计：

1. **用户控制：** 可移动密码库始终是用户选择的加密目录，而不是 KeptNear
   云账号中的一条记录。
2. **一个产品、一个密码库：** 人类密码和开发者凭据使用同一个可扩展数据模型
   和根解锁边界。
3. **机器访问默认拒绝：** 配对只确认使用方身份，本身不会授予任何凭据权限。
4. **提供操作，而不是原始读取：** 机器接口请求范围明确的操作，不提供通用
   `secret.get`。
5. **不隐藏锁定：** 格式、备份、导出、迁移、发布和安全边界都公开记录。

本地优先是一种控制权和架构选择，并不自动等于绝对安全。

## 产品模型

KeptNear 由三个协同部分组成：

| 部分 | 职责 | 当前交付状态 |
| --- | --- | --- |
| macOS App | 人类密码库操作、解锁、审批、设置、恢复和审计控制 | 已在源码和未签名实验性 DMG 中提供 |
| Local Broker | 设备信任、使用方认证、授权、授权凭证和凭据操作 | 已在源码中实现并测试 |
| MCP 与 CLI | 基于同一 Broker 协议的结构化机器接口 | 开发者预览；已经打包但未面向最终用户激活 |

```text
人类控制
  macOS App ───────────────────────┐
                                   ├─ 可移动加密密码库
机器使用                           │
  MCP Host 或 CLI ─ Local Broker ─┘
                       ├─ 精确的使用方身份
                       ├─ 精确的凭据和字段身份
                       ├─ 经过批准的能力
                       └─ 有边界的授权有效期
```

### 可移动密码库

`.pswvault` 是一个加密目录，保存可移动的凭据数据、经过认证的修订、删除记录、
附件和恢复信封。用户可以将它放在普通本地目录，也可以放进由 iCloud Drive、
Dropbox、Syncthing、WebDAV 或其他文件工具传输的目录。

KeptNear 不运营这些服务，不读取它们的账号状态，也不声称它们一定完成了传输。
它们只是传输加密文件的不受信任通道。

### 设备本地信任

使用方身份、访问规则、授权凭证、审批、暂停设置和不含密钥内容的审计事件都保留
在当前设备上。它们不属于可移动密码库，也不会静默转移到另一台 Mac。

设备根密钥和机器使用方身份保存在不可同步的 macOS Data Protection Keychain
中。`~/.keptnear` 下的托管状态经过加密，并会在 App 被删除后继续保留，使普通
重装可以恢复同一套本地信任关系。显式重置是另一项需要用户确认的操作。

### 凭据使用方

使用方是任何请求 KeptNear 执行凭据操作的本地应用或工具。它可以是 MCP Host、
CLI 配置、开发工具或普通应用。一个使用方被描述为 Agent，并不会因此得到特殊信任。

每个使用方都有密码学身份。显示名称帮助用户识别它，但授权绑定稳定身份，而不是
可变名称、进程标签或自然语言描述。

## 人类使用体验

macOS App 的目标是在不使用终端的情况下覆盖正常密码管理工作：

- 创建、打开、解锁、锁定、关闭和重新打开本地密码库
- 管理登录信息、安全备注、信用卡、软件许可证、令牌、密钥、证书和自定义凭据
- 搜索、筛选、收藏、归档、复制、显示和拷贝
- 生成密码和 TOTP 验证码
- 自动清理受管理的剪贴板内容，并在安全事件发生时自动锁定
- 在本地执行密码健康检查，不向泄露查询服务上传数据
- 创建和轮换离线恢复工具包
- 导入、显式导出、备份、还原和处理同步冲突
- 在同一个人类控制面中管理已配对的应用和工具

对于不了解 Broker 或 MCP 术语的用户，界面仍然应当保持克制、原生和易于理解。

## 机器使用凭据

机器访问设计的目标是减少密钥扩散，同时不假装“经过授权的操作一定没有风险”。

### 首次使用简单，需要时再进阶

保存 API Token 时，用户只需要填写容易理解的名称和 Token。KeptNear 自动生成
稳定内部身份。HTTP Bearer Header、子进程环境变量等技术放置方式，稍后通过
引导式 Usage Profile 配置。

Usage Profile 是声明式、与服务提供商无关的使用模板。内置模板可以提供友好默认值，
高级用户也可以创建精确配置。它不包含可执行脚本，也不包含密钥值。

### MCP 和 CLI 的入口不同

- **MCP** 面向已经支持结构化工具和类型化结果的兼容 Host。
- **CLI** 面向人类终端、脚本、诊断和直接子进程兼容场景。

两者使用相同的 Broker 身份、授权、操作和审计模型，不拥有独立密码库或另一套策略。

### 提供明确能力，而不是通用密钥输出

源码级协议当前定义：

- `credential.search`
- `access.request`
- `grant.status`
- `grant.revoke`
- `http.request`
- `process.run`

`credential.search` 只返回已授权且不含密钥内容的投影。`http.request` 将经过批准的
凭据放进一项明确的外部请求。`process.run` 可以把经过批准的凭据交给直接子进程，
用于兼容现有工具。子进程在得到密钥后可能继续保存或泄露它，因此 KeptNear 会记录
并解释这条边界，而不会声称撤销授权能够删除已经交付的密钥。

## 授权模型

规划中的最终用户授权流程：

1. 本地使用方证明自己持有身份私钥。
2. 用户在 macOS App 中确认配对。
3. 使用方针对精确的凭据字段请求一种能力，或者请求人工辅助匹配。
4. KeptNear 只向用户展示数量和内容都受限制的候选元数据。
5. 用户拒绝、仅允许一次，或者创建明确的可复用规则。
6. 授权凭证在允许的时间范围内放行这一项精确操作。
7. KeptNear 写入不含密钥内容的本地审计事件。

配对不等于授权，名称相同不等于授权，之前访问过另一个字段也不等于授权。

用户可以选择更方便的可复用规则，也可以要求每次操作都确认。KeptNear 负责执行
已配置的凭据范围，用户仍然需要决定给每个使用方多少自主权。

## 隐私和网络边界

KeptNear 不要求注册账号，当前版本：

- 不运营托管密码库或同步服务
- 不上传密码库、元数据、设备状态、审计、遥测或诊断
- 将 Usage Profile 模板离线打包
- 使用手动应用更新

以下场景仍然可能产生网络流量：

- 外部文件服务传输加密密码库文件
- 用户在浏览器中打开保存的网站
- 经过批准的 `http.request` 访问指定服务
- 经过批准的子进程自行使用网络

这些事实会被明确说明，而不是用“本地优先软件永远不会联网”这种不准确说法掩盖。

## 安全边界

KeptNear 旨在减少文件同步服务看到明文、意外留下明文、本地工具获得过宽权限，
以及普通机器接口结果输出原始密钥等风险。

KeptNear 无法防御：

- 操作系统或高权限进程被完全控制
- KeptNear 进程边界之外的键盘、剪贴板、内存或屏幕捕获
- 用户授权后恶意使用凭据的使用方
- 凭据操作获批后继续使用密钥的子进程或外部服务
- 密码库副本和有效恢复凭据同时被盗
- 过弱的主密码
- 构建或依赖供应链被破坏

项目尚未完成外部安全审计。当前未签名实验性版本不建议保存生产环境凭据。

## 当前范围

### macOS 首个完整版本闭环

- 完整的原生人类密码与令牌工作流
- 可移动文件同步密码库和明确的冲突处理
- 离线恢复、备份、还原、受控导出和迁移
- 本地 Broker、加密设备信任、配对、授权、审批、授权凭证、暂停和审计
- 受支持的 MCP 与 CLI 安装和生命周期
- 引导式 Usage Profile、Broker 代理 HTTPS 和兼容进程执行

### 不在首个完整版本闭环

- iOS 和浏览器插件
- Passkey
- 团队、共享密码库和企业策略
- 远程 Broker 或远程 MCP 控制
- 托管账号、托管恢复或 KeptNear 同步服务
- Agent Prompt、指令、仓库、命令或意图管理

首个完整客户端以 macOS 为先。未来 Windows 客户端与产品身份和平台中立的 Rust
核心兼容，但不属于当前交付计划。

## 通往 1.0

产品方向已经稳定，但兼容承诺尚未稳定。下面的里程碑表示闭环顺序，不代表发布日期。

| 里程碑 | 定义 |
| --- | --- |
| `v0.2.0-alpha.1` | 完善 macOS 人类密码库、令牌工作流、导航和公开产品体验。 |
| `v0.3.0-alpha.1` | 提供 KeePassXC 高保真迁移、迁移预览、明确损失报告和全新本地身份。 |
| `v0.4.0-beta.1` | 激活受支持的 Broker、MCP、CLI、配对、审批、升级和卸载生命周期。 |
| `v0.9.0-rc.1` | 冻结密码库与协议兼容面，验证升级和恢复，并完成签名与公证分发。 |
| `v1.0.0` | 对密码库格式、协议、迁移和核心行为做出稳定兼容承诺。 |

外部审查很有价值，并且在推荐生产环境凭据使用之前仍然需要完成；但开源和有限范围的
实验性预览不会声称这项审查已经发生。

## 成功标准

KeptNear 的首个完整产品应当满足：

- 正常密码管理工作不需要终端
- 非专业用户可以保存 Token，并批准引导式 Usage Profile
- 用户可以看清每个使用方能够使用哪些密钥字段
- MCP 和 CLI 工作流不再要求把 Token 粘贴进对话或持久化 shell 配置
- 移动或同步密码库不会静默转移设备信任
- 迁移、恢复、同步和导出失败时保留原始加密数据
- 源码、未签名版本、签名版本和生产使用建议始终保持独立且诚实
